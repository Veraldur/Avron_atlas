# QA — AvronAtlas v38 / Устойчивость реестра

Тестовый запуск: Chromium через DOM `page.set_content` для отдельных движков; Python, Node.js для данных/синтаксиса; проверки архива отдельно. **Полный исполняемый Phaser-UI и Windows EXE не запускались.**

## Подтверждённые проверки

1. Исходные ZIP: 603 + 282 Markdown; оба читаются без ошибок целостности.
2. Импорт: 885 новых документов Foundry без перезаписи исходных, 174 локальные иллюстрации; исходные 266 сущностей карты сохраняются.
3. Сводный индекс: 1 381 адресуемый материал (включая виртуальные проекции экспонатов), 912 статей, 3 книги Летописей; `AvronMaterials.audit().issues = 0` на проверенном тестовом мире.
4. Кнопка в `AvronLoreMatrix`: открывает статью пересечения через `AvronNav.open`; тестовый маршрут Летопись → статья → пересечение доступен.
5. Создание статьи с тремя родителями (`book`, `lore`, `entity`), обратные связи для всех трёх, отдельная связанная сценическая Летопись.
6. Удаление одного родителя не удаляет статью и остальных родителей; удаление статьи очищает ссылки на неё.
7. Создание объекта с многоугольником через `AvronMaterials.adopt('entity',e)` сохраняет поля и координаты, удаление удаляет запись.
8. Стартовая модель в `default-world-current.js` синхронизирована с отдельно поставляемым JSON v38 (раньше было расхождение).
9. **Обновление уже отредактированного сохранения v37**: первый запуск переносит 886 материалов (885 архивных + 1 технический тест), второй — **0**, ранее изменённый текст статьи остаётся без изменений, граф не получает битых ссылок.
10. Автоматическое разрешение Foundry wiki-упоминаний только по точным однозначным названиям: 11 неразрешённых, 1 неоднозначная вынесены отдельно.
11. Изолированный Chromium не выдал `pageerrors` в проверенных сценариях.

Точный машинный отчёт с результатами: `reports/BROWSER_TEST_V38.json`.

## Не проверено полноценно

- Реальный клик по любому объекту Phaser с активным Canvas и все комбинации перекрывающихся окон.
- Перезапуск реального Windows `.exe` и устойчивость его браузерного профиля.
- Полный ручной прогон **каждого** `Создать`, `Добавить`, `Удалить` в пантеоне, всех старых залах и редакторах мини-сцен.
- Восстановление после аварийного закрытия во время массового импорта; конкурентное редактирование одной базы.
- Автоматическая интерпретация неоднозначных wiki-ссылок и авторская проверка канона импортированного Foundry.
- Поведение большого количества внешних/нестандартных ссылок и стороннего HTML в Markdown; требуется отдельный security-проход перед публичной публикацией.

P1: старые формы мутаций, полная тестовая матрица кнопок, атомарные транзакции и совпадение author/viewer прав. P2: рендер производительности и новый ZIP-формат мира с бинарными вложениями.
