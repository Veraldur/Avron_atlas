# AvronAtlas · Архитектура ссылочного мира (v30)

## Две независимые плоскости
- **World / авторский JSON**: `entities`, `articles`, `showcases`, `explorerNodes`, `adventureRooms`, `chronicleBooks`, `pantheon`, `timeline`, `sections`, `maps`, `contentLinks`.
- **Viewer / локальный профиль**: `localStorage[avron.viewer.<worldId>.visited.v30]`. В него записываются только посещения, а не канон.

## Адреса материалов
Типизированная ссылка — `{kind, id}`. Примеры: `entity:b5823692`, `showcase:avron-amena-city`, `node:city-amena`. Один материал может иметь много входов; источник остаётся единым. `AvronNav.open(ref)` проверяет ID и открывает родной движок, не рисуя его второй раз.

| Тип | Хранится | Открывается |
| --- | --- | --- |
| `entity` | `entities` | Карта Phaser + редактор объекта |
| `article` | `articles` | Markdown-редактор / просмотр |
| `showcase` | `showcases` | Галерея / Зал / Комната / Город согласно `layout` |
| `node` | `explorerNodes` | Исследование города, района, дома, гильдии, региона |
| `room` | `adventureRooms` | Стартовая комната приключения |
| `book` | `chronicleBooks` | Летопись |
| `section` | `sections` | Исходный раздел |
| `god` | `pantheon` | Пантеон |
| `map` | `maps` | Атлас земель |

## Создание и редактирование
1. Автор выбирает объект на карте; панель «Материалы и переходы» показывает существующие привязки.
2. Нажимает «Статья», «Исследование», «Витрина», «Приключение»: если подходящая привязка есть, открывается оригинал; иначе в Редакторе создаётся новый материал со своим ID и ссылка `contentLinks`.
3. «Связать» позволяет привязать любой существующий материал без копирования. Созданная витрина автоматически регистрируется в меню.
4. Переключение формата витрины меняет `layout`, но автор остаётся в редакторе, а «Открыть выбранный формат» показывает выбранный движок. Это предотвращает потерю доступа к конфигурации «Комнаты», «Зала» и «Города».
5. Удаление материала должно удалять или помечать недействительные входящие ссылки. Диагностика `AvronNav.audit()` находит битые ID в `contentLinks`, `explorerNodes.links`, привязках комнат и витрин. **Проверка существования ID не эквивалентна браузерной проверке поведения.**

## Масштабирование 300–400 приключений / 80 домов
Один реестр ID, виртуализируемые/постраничные каталоги, ленивый поиск и индексы по `typeId`, `entityId`, `tags`; ссылки по ID вместо вложенных копий. Удаление не каскадирует на первичный объект, пока мастер не подтвердит это явно.

## Границы v30
Рефакторинг существующих самостоятельных визуальных движков на React не выполнен. Движки остаются в своих скриптах и открываются через адаптер. Для онлайн-хостинга потребуется серверное хранилище профилей и транзакционные операции; локальное сохранение браузера остаётся ограничено размером хранилища.
